The system at a glance

You talk to the web app. The web app talks to the API. The API runs the agents, which read the shop database and call the LLM (Anthropic Claude by default, or OpenAI / Groq).

Containers (code) SQLite files in data/ Your CSVs (read-only)

Request flow

What happens between pressing Enter and seeing the answer: about 5 seconds and $0.002.

You ask in the web app

For example, "Show monthly net revenue for 2023 as a line chart". The app sends it to the API along with the conversation id.

ui/app.py

The API starts the agent graph

The API loads the conversation from memory and starts a timer, so it can report latency and cost.

app/main.py

The router picks an agent

Numbers go to the Analyst agent, a request to see data goes to the Chart agent, and small talk goes to the Assistant.

app/graph.py

The agent works with its tools

The agent reads the tables, looks up what "net revenue" officially means, then runs SQL or draws a chart. It fixes and retries on any error.

app/tools.pyapp/knowledge.pyapp/charts.py

Guardrails check every query

Only SELECT statements are allowed. Queries run on a read-only connection and stop after 60 seconds.

app/data.py

Memory saves the turn

The turn is stored in memory.db. Once a chat passes 6 turns, older ones are folded into a short summary.

app/graph.pydata/memory.db

You see the answer

You get the answer, an interactive chart, which agent answered, the tokens, cost and time, and every step with its SQL.

ui/app.py

Data pipeline

This runs once, on the first start (about 3 minutes for 3.3 million rows). After that the app starts in seconds.

1 · Read CSVsEach file in data files/ becomes one table
2 · CleanEmpty cells become NULL, " UTC" is dropped from dates, postal codes stay text
3 · IndexIndex the id, order, user, product, status and date columns
4 · Swap inBuild under a temporary name, then rename, so a crash never leaves half a database
5 · Read-onlyThe agents open the database in read-only mode

New data? Update the CSVs (same file names), delete data/shop.db and start again.

Deployment

One image, two services. docker compose up --build is the whole deployment.

ServiceRunsPortReads / writes
apiFastAPI + LangGraph agents${API_PORT:-8000}data/ (read and write), data files/ (read-only), evals/
uiStreamlit web app${UI_PORT:-8501}Talks only to the API
Health check

The web app waits until the API is healthy, so it never opens before the data is ready.

Secrets

The key lives only in .env, which is listed in both .gitignore and .dockerignore.

Persistence

data/ is a volume, so data and chats survive restarts and rebuilds.

Portable

The same commands work on Windows and Mac. Ports can be changed with environment variables.

Run it

You need Docker Desktop running and an Anthropic API key (an OpenAI or Groq key also works).

1 · Add your key

In PowerShell, paste your key after ANTHROPIC_API_KEY=.

cd D:\insightly-lite
copy .env.example .env
notepad .env

2 · Start

Then open http://localhost:8501. The very first start loads the data, which takes a few minutes.

docker compose up --build

Ports busy?

$env:API_PORT=8100; $env:UI_PORT=8601; docker compose up

New data

docker compose down
del data\shop.db
docker compose up

Testing

Run these in a second window while the app runs. The commands are the same on Windows and Mac.

Backtest 1 · free

29 checks: row counts, data cleaning, all tools, 5 chart types, blocked writes, memory window.

docker compose exec api python tests/backtest.py
Backtest 2 · about 3 cents

17 real tasks scored on 10 metrics. Latest result: 17 / 17 passed, 0% hallucination.

docker compose exec api python -m evals.run
