The model reads each tool's description to decide when to call it. Errors go back to the agent, so it can fix its own SQL.

Lead with the answer in bold, then at most 2 short sentences of context.
Use $ for money and thousands separators. Don't paste the SQL; the app shows it.

Memory design

There are two layers, so chats feel natural without the prompt growing forever.

Layer 1 · everything, on disk

Every message, tool call and chart is saved per thread_id in memory.db by the LangGraph checkpointer. Chats survive restarts and can be reopened from the sidebar.

Layer 2 · what the model sees

The model sees the last 6 turns word for word, plus a summary of everything older. The window always starts at a question, so a tool call is never separated from its result.

Tested

In a 9-turn chat, the first 3 turns were summarised. The agent still recalled the user's name, their favourite category and a revenue figure from turn 2.

Cost

Price for claude-haiku-5-5: $0.10 per 1M input tokens and $0.50 per 1M output tokens (prompts up to 100K tokens; ours are about 2-6K). The same answers on gpt-5.4-mini cost about 8x more. Input is most of the volume (schema, prompt and history); output is short.

Why it's cheap

A mini model, short outputs, aggregation done in SQL rather than by the model, and memory that caps the history.

Where it's shown

The app shows the cost of every answer and the total for each chat. The API returns cost_usd, and evals/ reports cost per task.

Change the model

Set LLM_MODEL= in .env. Prices for other models are in app/config.py.
